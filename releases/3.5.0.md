# Alpha Squad UI 3.5.0 — Development candidate

## Personal Ultimate design 2

The selected personal HUD combines each native skill icon with the current Ultimate points, its verified native cost, a thin progress bar and a short localized state. Both normal weapon slots remain visible horizontally or vertically. The green left-side marker identifies the verified active bar; the other slot is dimmed. The HUD stays transparent, without ability names or repeated branding.

Normal Ultimate values can exceed their cost: `260 / 200` remains 260 points while the progress bar stops at full. An unknown cost stays `current / ?`; an empty slot has no invented cost or readiness. Transformation and temporary bars show their actual native Ultimate without presenting an ordinary bar as active.

Optional Overload keeps manual activation and cancellation. Its counter shows actual remaining Ultimate points, with a reserve marker on the bar. The ready-reminder threshold is a reminder, not the skill's cost. The states are neutral **INACTIVE**, gold **ACTIVE**, pulsing green **READY** and pulsing red **STOP**. French uses **INACTIF**, **ACTIF**, **PRÊT** and **STOP**. Language changes update the existing HUD immediately and preserve its placement.

## Native Ultimate slot

The personal HUD replaces only the native Ultimate button's visual presentation while the replacement is enabled and visible in gameplay. Turning off **Show personal HUD**, hiding the personal tracker or disabling ULT Tracker restores the native slot, including when group tracking remains enabled. Menus, loading and MOVE HUD release the replacement; returning to visible personal tracking applies it again. Ultimate casting and its keybind remain native. Other action buttons and sharing preferences are unchanged.

## Placement and validation

New personal layouts default to 316 × 48 logical UI units horizontally or 152 × 108 vertically. Existing saved placement and dimensions are preserved. MOVE HUD retains explicit orientation, proportional scaling and isolated examples.

The 3.4.1 dropdown naming correction is retained. The reported 3.4.0 `BG` / `Scroll` initialization failure remains recorded; no native retest has yet been reported for that correction or this candidate. Test both selectors again along with keyboard/gamepad action bars, enable/hide/disable restoration, combat, loading, special bars, both orientations, language changes and other action-bar addons. Follow the [3.5.0 acceptance route](../docs/SUPPORT_COVERAGE_TESTING.md#350-personal-ultimate-acceptance) and record the exact build in [client acceptance](../docs/CLIENT_ACCEPTANCE.md).

Automated checks validate logic and packaging, not native rendering, frame time or coexistence. This candidate belongs on `dev`; this cycle authorizes no PR, merge, tag, GitHub Release or ESOUI publication. Formal transport reservation and multiplayer coexistence evidence remain separate outstanding requirements.
