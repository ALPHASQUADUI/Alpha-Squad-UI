# Development audit — 3.4.0

Scope: `dev` starting at `1f23c75d3c7c962e363633e1441244a4297f0e6c`, the supplied personal Ultimate screenshot and the full addon/companion runtime, data boundaries, settings, packaging and tests. Changes implement the requested interface direction; they do not establish native ESO acceptance. Code and documentation stay English; the French interface is explicitly authorized.

## Findings and improvements, highest priority first

1. **Medium correctness — localized potion and Champion evidence: corrected.** Potion categories previously depended on English substrings, and support scoring matched English Champion names without proving allocation. `SupportCoverageScanner.lua` now uses native localized potion trait descriptions and verified active Champion IDs, with duplicate IDs excluded. `SupportCoverageShare.lua` matches reviewed native effect identities for category hints. This never proves consumption or an active group buff. Scanner regressions cover French names, missing native data and inactive/duplicate Champion stars.
2. **Medium action clarity — personal Ultimate ambiguity: corrected.** AUTO/FRONT/BACK selection could hide the other weapon slot; title, bar headers and skill names competed with readiness. Both ordinary weapon slots are now visible in a transparent compact HUD, with a green left-side active-bar marker and a dimmed inactive icon. Invalid native slots clear stale effect metadata, unknown cost stays unknown, and spending clears stale READY immediately. Special/temporary native bars present their real active slot instead of pretending unavailable weapon bars are actionable.
3. **Medium lifecycle/performance — scans despite native sharing OFF: corrected.** Stored sharing consent could keep full captures running after Dashboard tracking and actual native sending were OFF. The refresh path now skips expensive work while retaining dirty flags, combat/loading cleanup and bounded wake checks. A peer request while native sending is OFF is rejected before capture/encoding; receiving permitted summaries remains independent. Regression counters verify zero capture/output and later ON recovery.
4. **Medium ergonomics — scene return, focus and scale: corrected.** Main Close/Escape returns gameplay; placement Done/Escape selects Alpha Squad in native keyboard Settings. Cancellation, combat, loading or an intervening dialog cannot reopen a canceled return. Orientation controls sit beside each eligible HUD, respect inherited scale and stay reachable at screen edges. Gamepad retains the direct shell return fallback. Every movable module exposes Move HUD.
5. **Medium localization — coherent live language change: corrected with native acceptance pending.** Dashboard offers automatic game language, English and French. Explicit selection is account-wide; automatic mode remains automatic across client language changes. Bindings refresh existing controls and dynamic views without build requests or rescans. Cached readiness translates templates while preserving player names. Format placeholders are checked; literal percentage prose is not mistaken for a formatting directive. Native names and native tooltips stay in ESO's own language; no guessed official item/skill translations are supplied.
6. **Low visual clarity — noisy gameplay framing and overlaps: corrected.** Gameplay HUDs lose orange panels, repeated brand and redundant headers; main settings retain the orange accent. Personal HUD defaults are 152×80 horizontal or 72×168 vertical, with saved custom geometry preserved. Group rows use steady readiness and no full-row pulse. Support/Builds headers reserve space for actions/counts/icons; long labels use bounded wrapping or ellipsis with hover detail. Native font metrics and all resolutions still need client checks.
7. **Low correctness — group status priority: corrected.** Offline/dead now outranks a recently used Ultimate. The group renderer reuses its controls and handlers; an empty solo roster no longer runs recovery polling. Group regressions cover priority, live language changes and timer suspension.
8. **Low performance — duplicate detailed-build encoding: corrected.** A valid request encoded one capture twice. The transport now reuses only the bounded body attached to that identical local snapshot. Invalid captures still emit no traffic, and prepared bytes from an older snapshot are rejected. Wire format, chunk pacing and retry limits are unchanged.
9. **Open native validation — release confidence.** Test French and English with real font metrics, 720p/1080p/ultrawide and actual UI scales; both orientations; weapon swaps; empty/unknown/transformed bars; Overload active/ready/stop; settings return and controller fallback. Record frame-time and memory in solo, four-player and twelve-player sessions. Automated layout mocks cannot prove text never overflows in the client or establish an FPS gain.
10. **Optional future resilience — interrupted detail transfers.** Losing an intermediate fragment/acknowledgment currently ends in a bounded timeout and a new user request. This is fail-closed behavior, not an observed data leak. If native measurements show frequent failures, consider a limited retransmission with idempotent acknowledgment handling while preserving memory, queue and total-duration bounds. No speculative retry system is added in this interface update.

## Security and privacy assessment

No new critical security defect was demonstrated in the reviewed code. That statement is scoped, not proof of absence. Current transports verify group/session identities, consent, type/range/size/version, current build fingerprint and bounded lifetime before accepting detailed data. Unknown/incomplete evidence does not become confirmed coverage. Saved preferences, native OFF and optional-library degradation remain intact. Real group data, private captures and credentials are not added to the repository or packages.

The archive gate checks approved paths, manifest completeness, transformed companion content, identity policy and recognizable credential patterns. The publisher still requires exact source/artifact provenance and never overwrites published tags/assets. Protocol registration/coexistence and native acceptance remain incomplete; this task neither asserts nor changes external administrative settings.

## Validation and limits

Run `python3 tooling/validate.py` with Lua 5.1 and Lua 5.4. It executes Python security/release tests, checks Lua/manifests, packages both addons and runs regressions against the extracted ZIP contents. The complete development preflight passed; delivered hashes and source revision are in the bundle provenance. GitHub CI must also pass after the development commit is pushed; local validation is not a remote CI result.

Targeted additions cover bilingual binding/format safety, catalogue text, native data isolation, transparent HUD geometry, live same-language refresh, scaled orientation buttons, scene return, unknown/spent Ultimate states, localized potion/Champion handling, native-OFF scan suppression and single-pass encoding. These tests establish logic and bounded work; they do not certify appearance, network coexistence, frame time or a universal 10/10 rating.

The maintainer's earlier 3.3.1 acceptance is historical. The 3.4.0 cycle still requires the [client checklist](SUPPORT_COVERAGE_TESTING.md#340-interface-acceptance). Work stays on `dev`; no PR, merge, tag or release is authorized. Only a human may approve and merge any future PR.
